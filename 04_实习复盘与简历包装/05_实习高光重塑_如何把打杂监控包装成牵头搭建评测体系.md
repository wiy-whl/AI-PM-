# 实习高光重塑：如何把“打杂监控”包装成“牵头搭建 AI 代码评测体系”？

实习生最常踩的坑是：在简历上老老实实写“监控后台数据，收集用户反馈，推进 Bug 解决”。这种描述在面试官眼里就是纯纯的“打杂客服（Operation/Support）”。

你要应聘的是 AI 产品经理/评测专家。我们必须把你做的这些碎活，**升维、重组，包装成一个从 0 到 1 建立标准的“大工程”**。

这套话术为你量身定制（基于腾讯大模型 + 内部类 Cursor 插件 + 协调测开/研发的背景）：

---

## 一、简历怎么写 (Resume Bullet Points)

**项目名称**：集团级 AI 智能编程助手 (基于腾讯混元大模型)
**项目角色**：AI 产品实习生 - 评测与迭代核心骨干

> *   **【从 0 到 1 搭建基线】**：针对内部类 Cursor 代码插件初期“生成质量无法量化黑盒”的痛点，牵头定义并搭建了内部首个《AI 代码生成评测集 (Eval Dataset)》与验收基线。
> *   **【深度数据挖掘】**：非粗放式抽样，而是深入 IDE 后台监控数据流，提炼 500+ 个高频真实开发场景 (涵盖 Java/C++、跨文件引用、内部 RPC 框架)，将其转化为带有明确“断言通过标准 (Assertions)”的黄金评测题库。
> *   **【跨端敏捷协同】**：作为评测中枢，向上协调测试开发 (SDET) 团队打通了自动化“沙盒编译验收流水线”；向下反哺大模型算法与 IDE 前端团队，用精准的 Bad Case（如：腾讯模型对内部专有语法库的幻觉率高）驱动 RAG 检索链路与系统 Prompt 的优化。
> *   **【业务成效】**：将内部插件的代码采纳率 (Acceptance Rate) 从初始的 XX% 提升至 XX%，使模型迭代从“凭感觉测”跨越到了“自动化量化卡点”时代。

---

## 二、面试怎么讲 (STAR 面试逐字稿)

**面试官**：“在这个内部代码插件的实习中，你具体负责了什么？你平时是怎么和测开、研发配合的？”

**你的满分降维打击回复：**

**(Situation 痛点导入)**
“其实我刚接手这个项目的时候，我们基于腾讯大模型做出的类 Cursor 插件已经在那跑了。但我发现一个极其致命的黑盒问题：**我们根本不知道它到底好不好用**。
因为作为实习生，我每天都在看后台数据和用户群，用户今天骂‘这代码胡说八道’，明天说‘报错了’。我们的算法研发也很无语，因为他们调了参数，根本不知道在大盘上是变好了还是变差了。全靠瞎子摸象。”

**(Task & Action 出招)**
“我意识到，不能再单纯当一个传话筒了。我必须建立一套**『客观的尺子』，也就是代码评测集**。我的工作分成三步，极其依赖各部门协同：

*   **第一步：找真实的弹药（我本人的活）**。我把后台数据里，用户采纳率最低（也就是写完立刻被用户删掉）的代码片段捞出来。我发现腾讯大模型做通用 Python 很好，但一遇到我们集团专用的内部 RPC 框架，甚至子公司的闭门业务代码，它就开始发梦（幻觉）。我把这些真题，整理成了包含 300 道硬核场景的 Golden Set（黄金评测集）。
*   **第二步：协调测试开发（测开团队）**。评测集不能靠人肉看，我去找了测开主管。我要求测开帮我拉起一台隔离的 Docker CI 流水线。以后我把评测集的 300 道题输入给咱们的插件，测开的流水线必须去 `build` 编译一遍大模型吐出来的代码。如果报 `SyntaxError`（语法错误），直接在我设计的看板上打 0 分。
*   **第三步：反哺算法与 IDE 研发（开发团队）**。有了这套系统，评测结果出来后，我拿着数据找算法团队就不再是扯皮了。我直接给他们定点数据：‘兄弟，这版模型咱们在跨文件调用的 Pass@1（首次编译通过率）暴跌了 15%，你是不是把本地依赖库文件提取模块改坏了？’。同时我也反馈给 IDE 插件团队：‘生成超过 10 秒的时候退出的用户激增，大家等不及，必须加一个流式（Streaming）卡顿兜底动画’。”

**(Result 定调)**
“通过这种方式，我作为一个实习生，硬是把咱们这个基于腾讯大模型的内部产品，从过去的『玄学迭代』，拉进了必须要经过评测集卡点的『自动化流水线迭代』。不仅极大降低了研发测开因为推诿扯皮带来的沟通成本，也让整个集团内的代码采纳率实打实上升了。”

## 三、面试官必问追问：你认为评测集里的“好题”长什么样？

此时你可以再次展现你的架构视野：
> “做普通的 AI 评测，题目是‘讲个笑话’这种不可证伪的主观题。
> 但咱们是做类 Cursor 的评测！我的每道题，都是一个**带有断言的闭环**。
> 题目不仅包含：给出前三行代码让它续写（FIM 补全）；还必须包含隐藏的 `Assert` 文件跑单元测试。如果大模型补全的代码跑不通单测，在我这它就是失败。这叫**执行级评测 (Execution-based Eval)**，是目前业界最认可的代码评测规范（类似 OpenAI 的 HumanEval 标准）。”
