# 微信小程序 AI 学习助手：RAG 评测与指标搭建实战

在独立孵化 AI 微信小程序等轻量级 MVP（最简可行产品）时，很多 PM 容易陷入“把产品跑通就万事大吉”的误区。
然而，在顶尖大厂的面试官眼中，能够**通过科学的评测指标（如 RAGAS）驱动 AI 产品指标调优、实现降本增效**的 PM，才是具备真正增长潜力的“高级产品经理”。

本教程详细拆解如何在微信小程序 MVP 的学习助手场景中，落地 **RAGAS 闭环评测与指标优化**。

---

## 🔁 一、 为什么轻量级 MVP 也要做 RAG 评测？

在我们的“微信小程序 AI 学习助手”中，核心功能是让学生上传笔记或课本，然后向 AI 提问进行智能答疑与路径规划。

*   **面临的真实痛点**：
    1.  **回答质量参差不齐**：学生上传的笔记格式混乱（有 Markdown、有手写拍照文本），大模型经常“胡编乱造”（幻觉），把概念讲错。
    2.  **API 费用极高**：初期为了追求回答的完整度，每次检索都把 5 个超大 Chunk（每个 1000 字）塞进 Prompt 中，导致每次对话消耗几万个 Tokens，API 账单飞涨，难以负担。
*   **出招**：我不能单纯当一个业务 PM，我必须引入 **RAGAS (Retrieval-Augmented Generation Assessment) 评估体系**，通过定量打分来精确指导参数优化，平衡“回答准确率”与“Token 成本”。

---

## 📊 二、 RAGAS 评测指标的设计与落地

我们在应用层与 Coze 开发中台的 Workflow（工作流）深度结合，设计了三个维度的 RAGAS 闭环打分准则：

| 评测维度 (RAGAS Metric) | 核心定义 (What it measures) | 为什么对学生重要？ | 我们的量化手段 |
| :--- | :--- | :--- | :--- |
| **1. Faithfulness (忠实度)** | 大模型给出的概念解释和答案，是否**严格起源于**学生上传的课本/笔记片段（Context），而非模型自行编造。 | 政治、历史、医学等学科容不得半点概念性编造，必须严格依据课本。 | `Faithfulness Score` = (回答中可被 Context 证实的 claim 数量) / (回答中总 claim 数量) |
| **2. Answer Relevance (相关性)** | AI 的讲解是否直接、精准地回答了学生当前的疑问，有没有东拉西扯。 | 学生的耐心极度有限，必须在 3 秒内给出切中要害的解答。 | 通过语义相似度，计算“AI 回答”与“学生提问”的匹配度评分（0.0 - 1.0）。 |
| **3. Context Recall (检索召回率)** | 向量数据库是否成功在海量课本和笔记中，找到了解答这道题**最关键的那一页/那一句话**。 | 如果找的 Context 本身就是错的，AI 再聪明也只能“垃圾进，垃圾出”。 | `Context Recall` = (Context 中包含的标准参考答案条数) / (标准参考答案总条数) |

## ⚙️ 三、 核心优化动作：如何通过指标反馈进行调优？

通过第一周在后台日志中打捞 **200+ 个** 真实答疑 Case 进行 RAGAS 评测，我们发现：
*   **诊断结果**：系统的 `Faithfulness` 只有 71%，且单次对话 Token 消耗极高。
*   **原因分析**：最初的 Chunking（文本切片）策略太粗放，Chunk Size 定为 1000 tokens，导致 Context 中混入了大量与问题无关的“教科书废话”，大模型在冗余信息中被干扰，从而产生幻觉。

### 我主导实施了以下两大优化动作：

#### 1. 动态 Chunk 策略微调（Chunk Size Tuning）
*   **动作**：我将切片策略从“1000 tokens 粗放切片”微调为 **“200 tokens + 20% overlap（重叠区）”** 的精细化切片。
*   **逻辑**：较小的 Chunk Size 能保证检索出来的 Context 极度纯净、无噪音；而 20% 的 overlap 能确保跨页面的段落上下文逻辑不会被物理切断。
*   **结果**：`Faithfulness` 评分直接从 71% 跃升至 **92%**。

#### 2. 查询重写（Query Rewriting）与多路检索
*   **动作**：学生在小程序端提问往往口语化且简短（如“二战起因”）。我们前置了一个轻量级 LLM 查询重写模块，将简短问题自动拓展为 3 个不同维度的学术性问法再去向量库搜索。
*   **结果**：`Context Recall` 指标提升了 **25%**，避免了因学生问得模糊而搜不到正确答案的窘境。

## 📈 四、 商业与产品成效

通过这套 RAGAS 闭环评测与参数调优，我们在 MVP 阶段达成了惊人的商业指标：
1.  **极速降本**：由于 Context 更加纯净、体积更小，单次请求的 Tokens 消耗降低了 **40%**，大幅减轻了 MVP 孵化阶段的资金消耗。
2.  **回答质量飙升**：AI 智能答疑的问答准确率（Faithfulness）提升至 **92%**，次日留存率提升了 **15%**，成功在 0-1 阶段验证了基于大模型提供个性化教育方案的技术与商业可行性。
