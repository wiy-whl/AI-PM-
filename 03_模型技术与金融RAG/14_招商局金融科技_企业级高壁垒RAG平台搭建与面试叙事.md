## 🔁 一、 业务痛点与产品定义

### 1. 企业内部研发的“两大痛点”
*   **私有代码资产召回率极低**：金融集团内部有大量的专有 RPC 框架、特定业务库及遗留系统（Legacy Code），开源大模型在通用代码上表现很好，但在专有依赖上几乎无法正确生成，废卡率极高。
*   **黑盒迭代与数据脱节**：上线了编程插件后，算法团队根本不知道哪些推荐是好用的，哪些是被用户秒删的。缺少科学的反馈收集机制。

### 2. 产品解决方案（您的核心产品规划）
我作为 AI PM，深度参与了企业级**“AI 智能编程助手插件（基于 RAG 代码仓检索）”**的需求规划、架构设计与评测标准制定：
*   **检索重排架构**：混合检索（AST 语法树 + 语义向量）双路召回 + Cross-Encoder 重排序（Rerank）。
*   **合规隐私防线**：前置 PII 数据脱敏 + 向量库 Metadata-Level 细粒度权限过滤（防止敏感代码跨项目越权泄露）。
*   **隐性数据飞轮**：设计 **5 类隐性反馈埋点规范**（如击键采纳、Ctrl+Z 纠偏撤销、代码退格等），实现从 IDE 日志中自动捕获用户真实纠偏轨迹，利用 Label Studio 和 SFT 微调闭环驱动模型自进化。

## 🛠️ 二、 核心技术模块设计（PM 懂技术的底牌）

### 1. 自研代码仓 RAG 检索与重排（Hybrid Search & Rerank）
*   **为什么用 AST 混合检索？**
    *   代码不像普通的自然语言，它有严格的抽象语法树（AST）和调用关系。
    *   我们设计了基于 **AST 语法树的混合检索**：通过分析当前光标周边的依赖结构，同时拉起语义搜索（Semantic Vector）和基于关键字符的 BM25 检索，再利用 **RRF（倒数排名融合）算法**进行排名融合，把最相关的上下文拉回。
*   **Cross-Encoder 门阶过滤**：
    利用重排序模型（Reranker）对海选出来的 30 个代码依赖块进行二次打分，精准提取相关性最高的 **Top-3 核心依赖上下文**喂给模型，不仅使跨文件代码召回率提升 **32%**，还将首字延迟（TTFT）缩短至极速的 **1.2 秒**，大幅提升流式输出体验。

### 2. 金融级高合规隐私防线
*   **PII 数据脱敏（Privacy Masking）**：
    自动过滤并掩码代码和日志中包含的个人姓名、内网 IP 地址、员工工号等敏感字段（如将 `ip = "10.24.12.8"` 替换为 `[INTERNAL_IP_1]`）。
*   **Metadata-Level 细粒度权限过滤**：
    为每个存入向量库的代码切片绑定部门标签与项目安全密级标签（RBAC）。检索时，强制在向量层面带上用户的项目权限 Token，确保大模型从源头物理隔离敏感代码，杜绝越权调用的风险。

## 🔁 三、 Bad Case 驱动的数据飞轮（IDE 埋点设计）

如何建立数据闭环，是面试官必然深入拷问的深水区。我们要展现出极其严密、专业的产品埋点设计：

### 1. 5 类隐性反馈埋点设计
我们绝不让用户手工去点“大拇指赞/踩”，因为用户在写代码时极其反感被打扰。我们必须设计**隐性反馈埋点（Implicit Feedback Telemetry）**，从日志流中捕获用户的“纠偏轨迹”：

1.  **击键采纳（Tab Accepted）**：大模型生成推荐后，用户按下 `Tab` 键接受，记为一次“成功采纳”。
2.  **纠偏撤销（Ctrl+Z / Backspace Telemetry）**：用户按了 `Tab` 采纳后，在 3 秒内按下了 `Ctrl+Z` 撤销或长按 `Backspace` 删掉了该代码段。这触发了一次高价值的 **Bad Case 信号**（说明生成了有语法错误或不合逻辑的脏代码）。
3.  **部分修改（Partial Edit Distance）**：用户保留了生成的 80% 结构，但手动修改了其中 20% 的参数。通过计算编辑距离，自动标记修改内容。
4.  **超时截断（Timeout & Dismiss）**：生成推荐超过 3 秒，用户没有按 Tab 而是继续输入自己手写的代码，记为“自动拒绝”。
5.  **语法报错（Syntax Validation Error）**：后台的 Docker 沙盒编译器检测到生成的代码编译不通过，直接记为“无效生成”。

### 2. 标注 ROI 提升 5 倍与 SFT 数据工程
*   **自动化归因与 Label Studio 板块**：
    我们使用 Python 脚本，集成开源的多模型对打捞上来的 Bad Case 日志进行自动预评分，快速剔除 80% 无争议的常规错误（如模型 QPS 限流导致的截断）。
    将剩下 **20% 具有高专业度争议的样本**（如特定内部框架的调用错误）导入 Label Studio 看板，交由资深架构师进行专家二次标定。这种“漏斗形”标定策略将人工标注的 **ROI 提升了 5 倍**。
*   **SFT 黄金语料库**：
    我们将专家标定后的正确代码与错误生成的对照组，资产化沉淀为 **500+ 组 SFT 黄金语料库**，用于大模型代码补全（FIM 链路）的增量微调，成功使插件的**代码采纳率 (Acceptance Rate) 提升至 38%**，首次编译通过率（Pass@1）提升 **25%**。
