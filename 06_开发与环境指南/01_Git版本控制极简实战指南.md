# Git 版本控制极简实战指南 (AI/量化开发必备)

无论你是做量化因子挖掘，还是写大模型 Agent 架构，代码越写越多，没有版本控制就会是一场灾难（比如不小心删了跑通的代码，或者跟同事合并代码时全是冲突）。

**Git 是目前全球最流行的分布式版本控制系统**。你可以把它理解为代码的“游戏存档系统”。

---

## 🚦 第一步：理解 Git 的“三个核心区域”

要用好 Git，必须在脑子里建立这三个区域的概念：
1. **工作区 (Working Directory)**：你当前正在写代码的地方（比如你的 VSCode 编辑器看到的文件夹）。
2. **暂存区 (Staging Area / Index)**：一个“购物车”。你把写好的代码装进去，准备结账（提交）。
3. **本地仓库 (Local Repository)**：结账后的“个人保险箱”。这里记录了你所有的历史提交版本（存档）。
*(还有一个 **远程仓库 Remote**，比如 GitHub, GitLab，用来备份和团队协作)*

---

## 🛠️ 第二步：单人开发的日常“四步曲”

每天写代码，你只需要熟练掌握以下几个核心命令：

### 1. 初始化一个项目 (建档)
如果你新建了一个文件夹，想用 Git 管理它：
```bash
git init
```
这会在当前目录生成一个隐藏的 `.git` 文件夹，这就是你的“账本”。

### 2. 查看当前状态 (核对)
随时可以用这个命令看看哪些文件被修改了：
```bash
git status
```

### 3. 把代码放到“购物车” (暂存)
你想把修改的代码准备存档：
```bash
# 添加所有修改过的文件到暂存区（最常用）
git add .

# 也可以只添加某一个单独的文件
git add quant_loop_usa.py
```

### 4. 提交进“保险箱” (正式存档)
打上标签，正式存档！
```bash
git commit -m "feat: 增加了大模型自动评估因子的逻辑"
```
*(注意：`-m` 后面必须写清楚你这次改了什么，这叫 Commit Message，方便以后回滚查找)*

---

## 🌍 第三步：与云端同步 (远程协作与备份)

代码总放在自己电脑上不安全，通常我们要推送到 GitHub/GitLab。

### 1. 绑定云端仓库
```bash
git remote add origin https://github.com/你的名字/你的仓库名.git
```

### 2. 把本地代码推送到云端 (Push)
```bash
git push -u origin main
```
*(第一次推送到 main 分支需要加 `-u`，以后直接敲 `git push` 就行)*

### 3. 把云端别人写的代码拉取下来 (Pull)
```bash
git pull origin main
```

---

## 🔀 第四步：分支管理 (Git 的灵魂)

不要永远只在 `main` (主) 分支上写代码！如果你想尝试一种极其疯狂的新因子挖掘算法，但怕把原来的代码搞崩，这时候就要**“开分支” (Branch)**。

1. **创建并切换到一个新分支**：
   ```bash
   # 比如你要开发一个 rsi 因子系统
   git checkout -b feature/rsi-alpha
   ```
2. **在新分支上随便改代码**：
   就算全盘崩溃死机，也不会影响主干。
3. **测试通过后，切回主干并“合并归档”**：
   ```bash
   # 先切回主分支
   git checkout main
   
   # 把那个分支的完美代码合并过来
   git merge feature/rsi-alpha
   ```

## ⚠️ AI / 量化开发者必看的 3 个“天条”

1. **绝对不要把海量数据传进 Git！**
   你的股票行情 `.csv` 文件、或者几百 GB 的大模型权重文件 `.bin` / `.pth`，**绝对不要** `git add .`。Git 只适合管代码文本，传大文件直接会导致 Git 瘫痪。
   * **解法**：在项目根目录新建一个叫 `.gitignore` 的文件，把不需要传的数据文件夹名字写进去。
     ```text
     # .gitignore 文件内容示例
     data/
     __pycache__/
     .env
     ```
2. **私钥和密码绝对不能上传（尤其是 .env 文件）**
   你的 OpenAI API Key 或者是量化数据库的密码，一旦 `git push` 到公开仓库，3秒钟内就会被黑客扫走并把你的额度刷爆。必须将带有密码的配置文件加入 `.gitignore`。
3. **“小步快跑，频繁 Commit”**
   不要憋了一个星期写了五千行代码才 `commit` 一次。每一次完成一个小功能（比如写完了一个测试函数），就应该 `commit` 一次。存档越多，以后找 bug 回滚的余地就越大。
