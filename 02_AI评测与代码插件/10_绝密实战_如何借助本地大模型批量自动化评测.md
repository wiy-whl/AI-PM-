# 绝密实战：如何借助本地大模型 (Gemma) 进行批量自动化评测？

既然你已经在本地安装了 Ollama 并运行了 Gemma，现在的核心任务是将“手动对话”提升为**“工业级批量跑测”**。

这不仅是技术活，更是 PM 的**成本与效率方案**。在面试中，这叫 **“构建闭环离线评测引擎”**。

---

### 第一步：环境配置 (The Engine)

确保你的 Ollama 正在运行，并且已经下载了模型：
```bash
ollama pull gemma:7b  # 或者 gemma:2b，取决于你的显存
```

---

### 第二步：编写批量评测脚本 (The Python Runner)

不要一个一个去输入。我们需要一个 Python 脚本逻辑：**读取测试集 -> 调本地 API -> 保存结果**。

创建一个文件 `local_eval_runner.py`：

```python
import json
import requests
import time
from tqdm import tqdm

# 1. 配置参数
OLLAMA_API_URL = "http://localhost:11434/api/generate"
MODEL_NAME = "gemma:7b"
INPUT_FILE = "eval_dataset.json"   # 你的 500 道题
OUTPUT_FILE = "eval_results_local.jsonl"

def call_local_gemma(prompt):
    """调用本地 Ollama API"""
    payload = {
        "model": MODEL_NAME,
        "prompt": prompt,
        "stream": False,
        "options": {
            "temperature": 0.1,  # 评测必须用低采样，保证结果可复现
            "num_predict": 512    # 限制输出长度，提升速度
        }
    }
    try:
        response = requests.post(OLLAMA_API_URL, json=payload)
        return response.json().get("response", "")
    except Exception as e:
        return f"Error: {str(e)}"

def run_batch_eval():
    # 加载数据集
    with open(INPUT_FILE, 'r', encoding='utf-8') as f:
        dataset = json.load(f)

    print(f"🚀 开始批量评测，目标模型: {MODEL_NAME}，总计 {len(dataset)} 条记录...")
    
    results = []
    for item in tqdm(dataset):
        # 构造 Prompt：这里体现你的 Prompt Engineering 功力
        prompt = f"""你是一名资深代码审计专家。请评价以下 AI 生成的代码。
上下文: {item['data']['context']}
AI 生成内容: {item['data']['ai_response']}

请给出你的评分 (0-100) 并说明原因。格式要求：分数: [数字] | 原因: [文本]"""
        
        start_time = time.time()
        output = call_local_gemma(prompt)
        latency = time.time() - start_time
        
        # 将结果存入 JSONL (防止脚本崩溃导致数据丢失)
        result_entry = {
            "id": item.get("id"),
            "prompt": prompt,
            "gemma_output": output,
            "latency_seconds": round(latency, 2)
        }
        
        with open(OUTPUT_FILE, 'a', encoding='utf-8') as f_out:
            f_out.write(json.dumps(result_entry, ensure_ascii=False) + "\n")

if __name__ == "__main__":
    run_batch_eval()
```

### 第三步：PM 的“深度思考”话术 (面试谈资)

如果你在面试中展示这段代码，记得配合以下**“产品决策逻辑”**：

1.  **关于并发与性能 (Throughput vs Latency)**：
    > “我没有使用多线程，因为本地 GPU 显存限制了并发。但我通过调整 `num_predict` 参数和设置 `stream: false` 优化了单次吞吐量。在我的 4090 环境下，处理 500 条 Case 仅需 X 小时，比公有云 API 受到 QPS 限制的情况还要快。”
2.  **关于一致性对齐 (Alignment)**：
    > “我专门测试了本地 Gemma 7B 与 GPT-4 在判分上的一致性。我发现小模型容易给『人情分』。于是我通过 **One-shot Prompt (给它一个判分范例)** 强行纠偏，让它的打分标准向严苛的专家看齐。”
3.  **关于数据脱敏与内网环境**：
    > “这套方案的真正意义在于：我们不用再把集团的交易核心代码发给外部 API。整套流水线跑在局域网内，实现了**『数据合规性』与『模型预演』的闭环**。”
