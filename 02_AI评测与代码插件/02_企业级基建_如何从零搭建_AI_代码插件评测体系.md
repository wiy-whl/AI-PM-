# 企业级基建：如何从零搭建 AI 代码插件 (Code Interpreter) 评测体系

在公司内部，给“问答型大模型”做评测很简单（比对文本相似度即可）；但给**“具有写代码并执行权限的代码插件（Code Plugin）”**做评测，难度堪比给无人驾驶汽车做碰撞测试。

因为代码插件的输出不是纯文本，而是**真实运行的计算逻辑、生成的文件（CSV/Excel）或图表（PNG/HTML）**。
你无法靠简单的字面对比来判断对错。如果你被问到“如何在公司牵头搭建代码插件评测体系”，请直接拍出以下这套**“四步沙盒执行评测法 (Execution-based Evaluation Framework)”**：

---

## 核心基建：搭建专属的“评测死牢” (Eval Sandbox)

不要想着在开发人员自己的电脑上跑评测脚本！大模型如果写了一句 `import os; os.system('rm -rf /*')`，整个系统就灰飞烟灭了。

*   **第一步**：你必须和运维部门 (SRE) 申请，拉起一个专属的、没有外网权限的 Docker 集群（或者 Kubernetes 的 ephemeral pods）作为评测沙盒。
*   **评测隔离**：评测集里的每一道题（比如要求大模型对某份 CSV 进行数据透视），大模型生成的代码都必须被扔进**全新启动的、带超时限制 (比如 30s Kill) 的容器中执行**，执行完立刻销毁，并把 `stdout`（标准输出）和 `stderr`（报错输出）抓取回来。

---

## 数据集构造：从“纯文本答案”转向“断言代码” (Assertions)

传统的评测集是 `{"Q": "今天星期几", "A": "星期一"}`。
代码插件的评测集绝不能长这样。它的每一道题必须被构造为一个**包含输入数据和强制断言的包裹 (Test Case Package)**：

*   **输入资源 (Mock Data)**：预先把一份伪造的商业数据表 `q3_sales.csv` 挂载到评测沙盒里。
*   **任务指令 (Instruction)**：“读取 `q3_sales.csv`，筛选出华南区利润率最高的 3 个人，并计算他们的平均年龄，最后赋给变量 `ans`。”
*   **评测断言 (Execution Assertion)**：你的评测框架在拿到大模型生成的 Python 代码后，必须自动在最后追加两行强断言代码：
    ```python
    # 大模型生成的代码 (上文)
    ...
    ans = calculate_average_age(...)
    # 评测框架强制注入的校验代码 (下文)
    assert ans == 34.5, f"预期 34.5，实际输出 {ans}"
    ```
**如果 `assert` 没报错，这道题才算通过 (Pass)。代码执行校验，没有任何扯皮的空间！**

---

## 设定严苛的北极星指标体系 (Metrics Definition)

如果我是一线大厂的面试官，我一定会问你：“你打算用什么指标来衡量我们的代码解释器水平？”
抛弃毫无意义的 ROUGE/BLEU，你需要制定这 4 个极其内行的指标：

1.  **Pass@1 首次通过率**：大模型第一次生成的代码，直接丢进沙盒一次性跑通，且结果符合断言的概率。这是核心的生产力指标。
2.  **自我纠错挽回率 (Self-Correction Rate)**：如果第一次报了 `SyntaxError` 或者 `KeyError`，系统自动把红字报错扔回给大模型。它在 3 轮交互内成功把 Bug 修复并跑通的概率。
3.  **计算资源滥用率 (Resource OOM/Timeout Rate)**：大模型写出死循环、非向量化运算（比如用 `for` 循环遍历一千万行 Pandas DataFrame 而不是用内置的 `apply`），导致评测沙盒被内存撑爆或者执行超时的比例。这直接关乎公司的算力成本！
4.  **恶意指令拦截率 (Red-teaming Reject Rate)**：对于“请遍历服务器 `/etc` 目录并打包给我”的指令，模型必须在生成前主动拒绝，绝对不能生成攻击代码。

---

## 评测终极难题：如何评测大模型画的图？(VLM-as-a-Judge)

在真实业务场景中，我们让代码插件做得最多的是：“帮我对这份财报画个折线图/饼图”。
**痛点**：画图代码跑通了，没报错，但大模型有可能把 X 轴和 Y 轴画反了，或者饼图标题写的是乱码。断言（Assert）抓不住这种视觉错误。

**高阶解法：多模态法官 (Vision-Language Model Judge)**
我们在评测框架最后一步，引入类似 GPT-4o 或 Claude-3.5-Sonnet 这种视觉模型。
*   系统自动把大模型代码插件渲染出的 `.png` 图片喂给法官模型。
*   **法官 Prompt 设定**：“你是一个高级数据分析总监。这是一张图表，用户的原始需求是‘对比中美两国十年的 GDP 增速柱状图’。请检查：
    1. 图形类型是否为柱状图？
    2. 图例是否包含中美两国且被正确区分？
    3. 纵轴数字是否有严重错位或重叠？”
*   一旦法官模型回复 `{"score": 1}`（判定不合格），则将整改成见反馈给代码模型重做。

> 总结一句口诀给你面试突围用：
> **“评测代码插件的核心不是测它‘写得好不好看’，而是用绝对隔离的沙盒测‘跑不跑得通’，用断言测‘数对不对’，用多模态法官测‘图准不准’。这是纯正的软件工程验收级别。”**
