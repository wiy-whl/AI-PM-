# 剖析 AI 评测双引擎：审核官 (Candidate) vs 考官 (Judge) Prompt

在我们的 `EvalLoop` 系统中，存在两个截然不同的身份。在面试中，如果你能把这两个 Prompt 的**设计哲学差异**讲清楚，面试官会立刻认为你是懂行的高手。

---

## 🎭 引擎一：审核官 Prompt (system_prompt.md) —— "干活的员工"

**职责**：阅读 Alpha 表达式和规则，基于一套标准给出具体的评估和修改建议。
**模型**：通常用 `gpt-4o-mini`（便宜、速度快，适合批量干活）。

### 核心结构拆解：

1.  **明确角色与职责 (Role & Mission)**
    *   *Prompt 节选*：`你是一名资深的量化研究员...任务是对...进行全面质量审核...`
    *   *设计哲学*：给模型设定一个“高智商、严谨”的 Persona，可以有效收敛它的表达风格，避免它用轻佻的口吻回答严重的故障。

2.  **量化评估维度 (Scoring Dimensions) —— 【核心亮点】**
    *   *Prompt 节选*：`[权重: 40%] 逻辑先验性... [权重: 30%] 工程健壮性...`
    *   *设计哲学*：**不要让模型自己发明标准**！PM 的核心价值就在这里。你把模糊的“质量好”，强行拆解为客观的、可量化的 4 个维度。这就像给阅卷老师发了标准的“评分细则”。

3.  **强制的输出结构 (JSON Schema)**
    *   *Prompt 节选*：`{ "total_score": 0, "verdict": "...", "fail_reasons": [...] }`
    *   *设计哲学*：工程链路需要的是 JSON，不是自然语言。通过定义清晰的 key，我们可以让系统直接把 `fail_reasons` 存进数据库。

4.  **业务红线与负向约束 (Negative Constraints)**
    *   *Prompt 节选*：`不得为没有经济学逻辑的 Alpha 给出 PASS 结论...`
    *   *设计哲学*：大模型天生带有一点“讨好型人格”（Sycophancy），它倾向于给用户通过。必须用强烈的负向约束，逼迫它做“恶人”。

## ⚖️ 引擎二：考官 Prompt (judge_prompt.md) —— "核检的主管"

**职责**：不看具体的代码，只看“人类专家答案”和“审核官的答案”，判断审核官有没有失职。
**模型**：必须用 `gpt-4o` 甚至更强的模型（因为评判别人的对错，需要更强的逻辑推理能力）。

### 核心结构拆解：

1.  **切断业务干扰，聚焦元评估 (Meta-Evaluation)**
    *   *Prompt 节选*：`你的任务不是去评价 Alpha 本身，而是评价另一个 AI...`
    *   *设计哲学*：如果没有这句话，Judge 模型很容易自己跑去算 Alpha 的结果。你要明确告诉它：“你是主管，你只管员工做对没做对”。

2.  **五档离散评分标准 (Likert Scale)**
    *   *Prompt 节选*：`5分 (完美)... 3分 (及格)... 1分 (完全错误)...`
    *   *设计哲学*：如果让大模型从 0 评到 100，它的方差极大。业内（如 RAGAS 或 OpenAI Evals 框架）主流做法都是采用 **1-5 档离散打分**，并为每一档写上极其具体的“行为描述”（Rubric）。

3.  **非对称惩罚机制 (Asymmetric Penalty) —— 【面试绝杀手段】**
    *   *Prompt 节选*：`误判 FAIL -> PASS 比 PASS -> FAIL 严重 5 倍！`
    *   *设计哲学*：在金融和医疗场景中，“漏报风险”比“误报拦截”严重得多。把烂因子放进实盘会亏钱，把好因子拦截了只是重写一次。**在 Prompt 里注入业务容忍度，是高阶 PM 的标志。**

## 🎯 面试话术：如何抛出这个亮点？

> **面试官**：“你觉得写 Prompt 是一门玄学吗？”
>
> **你（成竹在胸）**：
> “很多人觉得是玄学，是因为他们没有区分使用场景。
>
> 在我设计的 EvalLoop 评测流里，我把 Prompt 严格分为两种：一种是给 **Candidate** 的执行类 Prompt，核心是‘结构化和多维度约束’；另一种是给 **Judge** 的评判类 Prompt，核心是‘Likert 量表和业务容错不对称性’。
>
> 例如，我在判断 Judge Prompt 中明确规定，把烂因子误判为 PASS（漏报）的惩罚权重，是将好因子误判为 FAIL（误拦）的五倍。这就是把我们的**业务风控底线，写进了 LLM 的系统指令里**。这已经脱离了玄学，是一种可量化的工程手段。”
