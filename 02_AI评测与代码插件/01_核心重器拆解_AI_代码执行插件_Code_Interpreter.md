# 核心重器拆解：AI 代码执行插件 (Code Interpreter Plugin)

当面试官或业务方提到“AI 代码插件”时，他们通常指的不是调用外部 API（比如查天气的 Plugin），而是大模型领域最强大、也最危险的组件：**Code Interpreter (代码解释器插件)**。

它允许大模型在云端沙盒中自主编写 Python 代码，并**当场运行得出结果**。比如 ChatGPT 的 Advanced Data Analysis 功能。
作为 AI PM，这是你必须拿下的高阶知识点，特别是在你具备量化分析或金融背景的情况下。

---

## 深刻认知：普通 Plugin 与 Code Plugin 的根本区别

如果说普通 Plugin 是让大模型变成“接线员”（帮忙按图骥调用接口），那么 Code Plugin 就是让大模型变成“拥有化工厂的科学家”。

*   **普通 Plugin (API Calling)**：大模型受限于你写好的几百个函数字典。你没写 `画图()` 接口，它就画不了图。
*   **代码插件 (Code Plugin)**：大模型拥有一个完整的 Linux/Python 运行环境。只要有库（如 pandas, matplotlib），任何你想得到的高维组合动作，它都能通过写代码当场实现。

> **面试爆杀观点**：“在数据密集型的金融/量化场景，我们早已抛弃了让穷举开发无数个『算均线参数』、『查最大回撤』的小 Plugin。我们直接为大模型挂载代码插件。大模型遇到复杂诉求，自己写一段 Pandas 数据处理脚本，扔进沙盒里跑出结果图表返回给客户。”

---

## 架构拆解：隔离沙盒 (Sandbox) 是命门

如果你向公司申请引入 Code Plugin 服务，安全合规部门（尤其在招商局这种金融机构）会立刻跳出来阻止你：“让大模型瞎写代码在我们服务器上跑？万一它写个删除全库代码怎么办？”

你的回应必须体现架构层面的专业隔离：

1.  **物理环境隔离**：Agent 跑代码的环境，必须是与宿主机完全隔离的 **Docker 容器或极微虚拟机 (MicroVM，如 AWS Firecracker)**。它跑在一个临时的一次性环境里，查不到公司的真数据库。
2.  **网络隔离 (Air-gapped)**：这个沙盒必须被**拔掉网线**。大模型写出来的 Python 代码，不能发起任何向外的 HTTP 请求（防止它被恶意提示词诱导去内网扫描或者挖矿）。
3.  **计算配额限制 (Resource Quota)**：严防大模型写出死循环 `while True:` 导致服务器死机。沙盒必须设置 30 秒执行超时 (Timeout) 和内存占用上限 (OOM Kill)。
4.  **一次性生命周期**：每次会话结束（甚至每次运行结束），这个沙盒容器立刻 `kill` 掉销毁，不残留任何挂马程序。

## 评测体系：我们到底在测 Code Plugin 的什么？

对于代码插件，评测（Eval）不是看他这句代码有没有报错，而是考察以下能力：

### 1. 语法闭环与自修能力 (Self-Correction Rate)
*   **核心指标**：大模型第一次写出的代码如果报错了，沙盒把 traceback 也就是报错红字扔回给它。大模型能在 **3 轮对话内** 自己把 Bug 修好并跑通的概率是多少？（业界目前顶级水平如 Claude 3.5 Sonnet 或 GPT-4o 约为 70%-85%）。

### 2. 多步数据流转能力 (Multi-step Logic)
*   **核心指标**：如果你给它丢了一份带有残缺值 (NaN) 和格式错误日期的 `.csv` 表格。它能否精准命中这三步连招：清洗残缺值 -> 日期格式化转时间戳 -> 执行正确的分组汇部 (Groupby)。错一步数据就全盘崩溃。

### 3. 环境探伤能力 (Environment Probing)
*   **高维度评测点**：当大模型试图 `import talib`（一个量化库），却发现沙盒里没安装。它会不会直接崩溃说“我做不到”？还是它能聪明地转而使用自带的 `pandas` 手搓一个算出均线的逻辑替代品？（这叫退化适应能力）。

## 你该如何把 Code Plugin 讲进你的答疑/经历中？

> **演练话术参考**：
> “在处理金融用户那些极度零散、且强定制化的数据查询（比如：‘帮我把过去 10 天涨幅超过 5% 的股票全挑出来并画个散点分布图’）时，传统的 API Plugin 路线走不通，因为你不可能预先写好一个专门画这种散点图的定制接口。
>
> 我的策略是引入 **Code Execution Sandbox（代码安全沙盒）**。
> 对于这些『长尾且需要强数学计算』的需求，我不要求系统在后端准备好死板的 API，而是由大模型按需现写几行 Python 分析脚本。
>
> 这里的难点不是大模型会不会写 Pandas，而是**安全架构和状态共享**。作为 PM，我首要定义沙盒的物理边界（断网、限时、一次性销毁），并且明确了文件在宿主系统和大模型沙盒之间的挂载传输协议（把 `.csv` 以 `read-only` 映射进去）。这让我们的意图覆盖率，在不用开发新接口的情况下，提升了数量级。”
