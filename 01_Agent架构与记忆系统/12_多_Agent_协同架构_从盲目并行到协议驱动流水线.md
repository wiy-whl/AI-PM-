# 多 Agent 协同架构：从“盲目并行”到“协议驱动的流水线”

在面试高阶 AI PM 岗位时，一旦聊到“多 Agent 框架 (Multi-Agent)”，如果你的回答只是“用多个大模型一起聊天”，你会被瞬间打上“外行”的标签。

工业级研发追求的不是 LLM 在对话框里七嘴八舌，而是**严格的边界隔离与确定的握手协议**。以下是从你提供的架构图中提炼出的核心高潜护城河话术：

---

## 核心认知重构：多 Agent 的本质不是“并行”，而是“切断上下文污染”

*   **新兵的误区（指挥者模式）**：写一个超级 Prompt，让 3 个子 Agent 和主 Agent 在同一个大群里聊天（比如利用 AutoGen 的全连接拓扑）。这会导致所有探索失败的碎碎念相互污染，Token 极速耗尽。
*   **架构师的正解（统筹者模式 Orchestrator Pattern）**：
    主 Agent（Orchestrator）作为大脑，绝不亲自下地干活。它把任务拆解后包给子 Agent。
    **【关键隔离点】**：每一个子 Agent 有自己完全独立的 `messages[]` 和本地沙盒字典（`.worktrees/agent-a`）。子 Agent 在沙盒里试错、报错、修 Bug 的几百个回合，主 Agent **完全看不见，也不需要看**。
    子 Agent 跑完后，只向上级回传一句摘要：“报告，数据清洗完毕”。这是将多 Agent 从“混沌系统”变成“可控工程”的基石。

---

## 防崩底层：为什么必须抛弃自然语言，改用“协议”通信？

面试官必问：“主 Agent 怎么把任务分发给子 Agent 并拿到结果？” 
（如果你回答：就在群里 `@` 它们说话，那就掉坑里了。）

**标准专业回答：**
> “多 Agent 之间绝对不能依靠自然语言的提示词来维系状态，大模型互相传话极易引发状态丢失。我主张引入**『结构化协议层 (Protocol Layer)』**。
>
> 我们的主辅 Agent 之间通过物理硬盘上的 `.team/inbox/{agentId}.jsonl` 消息队列进行通信。
> 每一条指派任务，都必须严格遵守数据结构：
> ```json
> {
>   "request_id": "r-001",
>   "from": "Orchestrator",
>   "to": "Sub-agent-A",
>   "status": "pending",  // 状态机：pending | approved | rejected
>   "content": "拉取 10 年行情数据"
> }
> ```
> 这是一个 **Append-only（只追加不修改）且崩溃可恢复** 的通信队列。这就把多大模型的交流，拉回到了传统微服务通信（RPC/MQ）的稳健轨道上。**没有协议的协作，就是制造灾难。**”

---

## 致命顽疾：多 Agent 幻觉级联放大 (Conformity Bias Cascade)

这是一个极其亮眼的高分点！

*   **病因**：大模型在微调时往往被训练成了“讨好型人格（Helpful）”。如果在多 Agent 聊天室里，Agent A 得出了一个错误结论，Agent B 往往不会反驳，而是顺着 A 的思路继续附和，Agent C 继续强化。最后，三个顶级模型会以“极高的置信度”达成一个愚蠢的错误共识。
*   **药方 (交叉验证体系 Cross-validation)**：
    为了打破这个“从众偏见链”，我们必须插入物理阻断。
    不要让 Agent 之间无脑互吹。当子 Agent 提交结果后，必须切断它与其它伙伴的通讯，引入：
    1.  **外部地面真理 (Ground Truth)**：用非 AI 的编译器代码（Pytest/Babel）跑一下它写的东西。
    2.  或者引入一个**完全不看上下文的历史白板审计 Agent**，作为冷酷的法官进行独立评审。

---

## 最佳实践总结：多 Agent 系统落地的“三不”原则

要在面试中展现你的顶层设计思维，可以最后抛出这三个限制原则（展示你的克制）：

1. **先有隔离边界，再谈并行协作。**
   每个子 Agent 必须圈禁在其独立的 `.worktrees/` 文件夹中，严禁跨 Agent 读写文件。
2. **严格限制衍生层数 (Max Spawn Depth)。**
   主 Agent 可以生出 3 个子 Agent，但子 Agent 不能无限繁殖孙子 Agent，深度限制最多 2 层，防止系统陷入无限递归黑洞（Fork Bomb）。
3. **“权限剥夺式”的最小系统提示 (Minimal System Prompt)。**
   给子 Agent 洗脑时，只给它发“工具列表 (Tooling)”和“沙盒路径”。**绝对不给**它灌输业务全局观（Memory）或高级策略（Skills），防止它自作主张越界破坏系统全局状态。
