# 实战第一步：构建一个 Agent 的落地起手式

很多初学者（甚至初级全栈工程师）在决定要“做一个 Agent”时，第一步往往是：打开 ChatGPT，开始长篇大论地写系统提示词（System Prompt）。

**作为吸收了上述满级架构心法的高阶 AI PM，请你记住：这是绝对错误的起手式。** 

要构建一个工业级落地的 Agent，第一步**永远是画“楚河汉界”（定义边界与物理约束）。**

当你面对一个新的 Agent 需求（比如：我要做一个自动挖掘美股财务因子的 Agent），你作为架构师或 PM，必须按顺序回答以下三个灵魂质问：

---

## 灵魂质问一：它“能”做什么？(Capability & Tooling Mapping)

不要去想“我要怎么教它写因子”，你要想“我要给它配几把什么样的专属斧头”。

*   **错误动作**：直接写 Prompt “你去给我下数据”。
*   **高阶起手**：盘点手头的 API 资源，定义外置工具库（Skills / Tools）。
    *   清单罗列：这个 Agent 需要 `fetch_financial_data()`（拉财报）、`run_worldquant_backtest()`（跑回测）、`query_local_stock_list()`（查本地股票池）。
    *   **架构定义**：好，这意味着我的核心路由层必须配置一套 Dynamic Skill Loading（动态技能加载）机制，并且要为这三个函数写好极其严密的 JSON Schema 描述卡片。大模型在开局时，什么都不懂，只有这 3 张卡片。

## 灵魂质问二：它“绝对不能”做什么？(Hard Constraints Design)

大模型天然喜欢天马行空。你的第一步防线必须做在物理层。

*   **错误动作**：在 Prompt 里写“求求你千万不要用未来函数”。
*   **高阶起手**：定义 Linter（代码检查器）和 Runner（执行沙盒）的拦截规则。
    *   你明确知道，因子挖掘最怕两件事：引用了未来几天的股指数据，以及公式嵌套太深。
    *   **架构定义**：第一步要求研发在执行环境外围，套上一个 Python 的抽象语法树（AST）检查器。如果生成的代码里出现了带有 `future_` 字眼的变量，或者嵌套深林大于 5，根本不要进入回测环境，直接由外围脚步强制打回。**这叫做“用物理法则取代道德说教”。**

## 灵魂质问三：一旦它出错了，系统的尸体该怎么收？(State & Error Archiving)

大部分人只考虑“Happy Path”（顺利走通的流程），但工业级系统 90% 的时间在处理错误。

*   **错误动作**：报错了就把几十行 traceback 原封不动发给大模型让它修，最后把模型搞死机。
*   **高阶起手**：定义外置状态机与记忆落盘规则。
    *   **架构定义**：我必须在云服务器建一个专门的文件夹 `.working_states/`。
        1.  我要规定一个 `status.json`，把这次挖掘的因子分几个阶段硬性写死在这里。
        2.  一旦跑回测炸了，错误日志必须写入本地 `.log`，绝不发进大模型的 Context。系统只给大模型注入一个简短的 `[Error Pointer]: 请读取刚才日志里的第三行报错，写一段反思。`
        3.  大模型写的这段反思，必须被切分进我设计的 `MEMORY.md` 核心事实舱中，并附带今天的时间戳。

---

## 面试高光总结总结（AI PM 起手式口诀）

> “如果接到一个新的 Agent 立项，我的第一步绝对不是打开代码编辑器去写 System Prompt。
> 
> 我的第一步是做**『系统物理隔离设计 (Physical Isolation Design)』**。
> 我会将整个项目拆分成明确的『三界』：
> 1. 大模型只负责纯净的逻辑调度（无状态的大脑）。
> 2. 下游脚手架必须剥夺大模型的执行权和校验权（设置 Linter 和沙盒拦截网）。
> 3. 所有的执行进度与错误记忆必须被抽离，安置于文件系统的外置状态机中（JSON + MD）。
> 
> 只有把这套防大模型乱跑的『手铐和轨道』打好了，我才会在最后一步去填充那个最不起眼的初始提示词。”
