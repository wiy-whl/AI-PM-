# AI PM 实战：如何利用 Coze/Dify 构建高效生产力 Agent

在面试中，提到“我为自己搭建了工具”只是第一步，如果你能说清**“我是怎么搭的”**，这展现了你的**架构思维**和**工具化能力**。

---

## 1. 案例一：PRD 审计助手 (PRD Audit Assistant)

### 💡 核心价值
解决 PRD 逻辑不闭环、格式不统一、关键核心点漏掉（如：异常流、埋点需求）的痛点。

### 🛠️ 构建四部曲

1.  **知识库 (RAG 层)**：
    *   **上传数据**：公司标准 PRD 模板、内部研发流程规范、过往优等生 PRD 案例、UI 设计规范文档。
    *   **作用**：让 Agent 知道“什么才是合格的 PRD”。

2.  **工作流设计 (Workflow 层)**：
    *   **Node 1: 内容解析** —— 提取 PRD 中的核心逻辑节点（如：交互路径、数据流入流出）。
    *   **Node 2: 逻辑比对** —— 将内容与知识库中的规范进行交叉比对。
    *   **Node 3: 风险发现** —— 专门检测“如果...则...”逻辑中缺失的异常处理分支。

3.  **Prompt 设定 (Prompt 层)**：
    *   **人设**：你是一名毒舌且严谨的高级架构师，你的任务是从技术视角审视 PRD 的漏洞。
    *   **任务**：检查 1. 逻辑自洽性；2. 边界条件覆盖；3. 埋点标准化程度。

4.  **接口集成 (Plugin 层)**：
    *   集成 **Feishu/DingTalk API**，实现文档更新后自动触发审计并将反馈发送给作者。

## 2. 案例二：数据清洗 Agent (Data Cleaning Agent)

### 💡 核心价值
处理海量脏数据，实现自动化格式对齐、去重和初步分析，把 PM 从 Excel 的“复制粘贴”中解放出来。

### 🛠️ 构建三阶段

1.  **数据映射 (Knowledge Base)**：
    *   **数据字典**：上传各业务线的数据定义（如：Status=1 代表已支付）。
    *   **清洗规则库**：定义日期格式（YYYY-MM-DD）、手机号掩码规则、异常值范围。

2.  **代码执行能力 (Code Node)**：
    *   **核心动作**：在 Coze 或 Dify 中通过 **Code 节点** 调用 **Python 脚本**（pandas 库）。
    *   **任务**：
        - 执行 `drop_duplicates()` 去重。
        - 执行 `fillna()` 填充缺失值。
        - 利用正则提取非结构化文本中的关键 ID。

3.  **多模型协作 (Multi-Agent/Step)**：
    *   **Step 1:** 基础物理清洗（逻辑/代码执行）。
    *   **Step 2:** 调用 LLM（如 GPT-4o）对清洗后的数据进行“业务语义总结”，识别出哪些数据属于“高价值异常”。

---

### 🪝 面试话术：如何吹这个“Agent”？
> “我构建这个 Agent 最大的挑战不是写指令，而是 **‘工作流的逻辑拆解’**。
> 比如在做【数据清洗 Agent】时，我意识到 LLM 处理数学格式并不完美。
> 因此我设计了 **‘LLM 决策 + Code 节点执行’** 的混合架构：让 LLM 做语义转换决策，让 Python 脚本做确定性的物理清洗。
> 这直接让我每周处理业务反馈的时间缩短了 **70%**。”
