# 高阶架构实战：如何安全放权，打造跨会话的“长程 Agent”？

很多团队在宣讲时声称自己的 Agent 能“全自动写完一个 App”。然而真正的内行（比如面试你的技术总监）知道：**阻碍 Agent 自主运行的主要矛盾，早已不是推理能力，而是脆弱的单次 Session（会话）状态机。**

当任务长达几个小时，如果大模型断网、上下文被 Token 耗尽报警、或者执行器死锁，整个单会话崩溃，难道要从第一行代码重新写起吗？

这篇文章拆解了目前最顶级的长程任务存续架构：**双 Agent 解耦与状态外置化**。

---

## 核心痛点：为什么不要在一个 Session 里做完所有事？

把长期任务（如：挖掘 100 个动量变种因子、搭建一个量化看板）都揉在一个大模型会话里，必然会遭遇两大死局：
1. **记忆挤兑死局**：尝试在单次对话里做完全部事情，上下文必定比进度条先耗尽。最后大模型连最开始的任务是什么都忘了。
2. **状态丢失死局**：如果只做完了一半，模型崩溃重启，新的对话框完全不知道前一轮的上下文进度，只能被迫从头开始。

---

## 破局解法：异步双 Agent 接力架构

高级护城河的设计：既然 Session 靠不住，我们就把系统做成**无状态的 (Stateless)**，把状态全部**外置化**。这需要拆分两个专职 Agent。

### 角色 1：Initializer Agent (破冰者：一生只跑一次)
*   **任务**：只负责将模糊的需求，翻译成极其严格的“外部控制对象文件”。
*   **动作**：
    1. 生成一个 `feature-list.json` (功能清单，所有任务的 `passes` 初始为 `false`)。
    2. 生成项目初始状态，甚至是一个基础的 `git commit`。
    3. 生成一个统筹进度的 `progress.txt`。
*   **退出**：干完这三件事，它的 Session 历史使命就结束了，立马关闭。不带走一片云彩。

### 角色 2：Coding Agent (打工人：跨会话无限复活)
*   **任务**：循环干活。它是可以随时重启、随时崩溃的。
*   **单次循环 SOP**：
    1.  开启新 Session。
    2.  读取物理硬盘上的进度文件（从 `feature-list.json` 里找一个 `passes` 为 `false` 的任务）。
    3.  写代码、跑测试，搞定这一个功能。
    4.  **最高光的动作：改写物理世界的状态**。把 `json` 里的那个任务标为 `passes: true`，提交一个 `git commit`。
    5.  退出当前 Session。
*   **防崩机制**：即使干活干到一半系统内存溢出关机了。下次开机重启一个新的 Coding Agent，它依然会去**读取物理文件**，发现原来刚才那个任务没完成，它会自动接着干。

---

## 为什么进度文件要用 JSON 而不是 Markdown？

面试时的隐藏加分项：
> “做 Agent 开发时，我们极力反对让大模型把任务状态（目前卡在哪一步了，下一步做什么）当做自由聊天的上下文记在脑子里。”

**任务状态必须是被显式化、结构化写明的外部控制对象。**

*   **反面教材**：用 Markdown 列 TODO list。大模型在反复正则匹配打钩时极易出错，而且很难让外部程序去读取校验。
*   **黄金标准**：使用严谨的 `JSON` 文件。这是写给外围脚手架程序去读的。
    ```json
    {
      "tasks": [
        {"id": "1", "desc": "挖掘因子 A", "status": "completed"},
        {"id": "2", "desc": "因子里程碑检查", "status": "in_progress"}
      ]
    }
    ```
    *在这个模型下：大模型的任何思考脱轨，都会被系统外的轻量校正脚本发现（比如脚本发现连着 3 个 Session 这个 json 的状态都没更新，就会强制注入一句 `<reminder>` 把大模型拉回正轨）。*

---

## 总结：向 面试官宣讲的高维理念

“真正高级的 Agent 自主度提升，并不是在系统 Prompt 里加一句‘你现在长大了，你可以自己做了’。那叫盲目放权。

工业级的放权，前提是做好了**基础设施的托底**。我最核心的两个架构动作是：
1. **解耦业务逻辑与会话生命周期**：拆分 Initializer 和 Executor 角色。
2. **状态物理机化**：剥夺了大模型用『工作记忆 (上下文)』来记进度的权力，强制将其进度状态通过 `json` 文件和 `git` 记录**外置化并转移到了文件系统里**。

在这种架构下，每一个 Session 都是随时可被抛弃、可无限重启的。跨会话传递灵魂的不是 Token，而是坚如磐石的文件系统和代码仓库。”
