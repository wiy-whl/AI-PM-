# 架构心法：Agent 记忆系统的“四层结构”与“混合检索”

在面试高阶 AI PM 或架构师岗位时，记忆系统（Memory System）是绕不开的深水区。初学者往往认为“记忆 = 向量数据库”，这是极其片面的。

真正的基础设施级设计，是**按 Agent 实际要解决的问题来分层**，而非按存储介质来划分。

以下是将复杂记忆架构转化为面试“降维打击”话术的核心拆解：

---

## 一、记忆系统并不是“打补丁”，而是基础设施

大模型本身没有原生时间线概念，会话一关，记忆全清空。
作为一个好的 PM，你必须知道：**跨会话的一致性 (Consistency) 需要一层单独设计的基础设施来承载。**

这四种记忆，从“活跃度（耗费 Token 程度）”到“持久度（存多久）”，形成了一个漏斗：

1. **上下文窗口 (Working Memory - 工作记忆)**
   * **角色**：当下正在处理的燃眉之急（当前任务最小信息）。
   * **特点**：存在于当前的 `messages[]` 数组中。极其珍贵（Token 数量受限且昂贵），必须主动折叠或清空，会话结束即消亡。
2. **Tools / Skills (Procedural Memory - 程序性记忆)**
   * **角色**：教 Agent “怎么做某件事”（诸如查股票接口、验证公式规范）。
   * **特点**：作为外挂功能包存在，按需加载，**绝不默认常驻**。
3. **JSONL 会话历史 (Episodic Memory - 情景记忆)**
   * **角色**：记录“过去发生了什么”（原始对话快照）。
   * **特点**：全量写入本地磁盘做持久化。日常隐藏不消耗 Token，但支持被精准溯源和跨会话跨库检索。
4. **MEMORY.md (Semantic Memory - 语义记忆)**
   * **角色**：沉淀出的“稳定事实与规律”（比如“用户是喜欢做基本面挖掘的量化开发”）。
   * **特点**：由 Agent 自动提纯总结后写入。在每一次新会话启动时，被强行注入 System Prompt，定义全局调性。

*(记忆方法：工作在脑子，技能挂腰上，流水账存日志，个人偏好刻在骨头里)*

## 二、行业实战对比：ChatGPT vs OpenClaw

在面试中，要证明你的架构视野，最好的方式是对比两个真实系统的解法。

### 1. 偏向产品的解法：ChatGPT (极简的四层设计)
很多人惊奇地发现，ChatGPT 并没有用什么高大上的外挂向量数据库或 RAG，它只依靠以下四层轻量级设计就做到了几千万人的好评：
*   **第 1 层 (临时)**：设备/地点/Session 相关 Metadata (不持久化)
*   **第 2 层 (定海神针)**：约 33 条关键偏好事实（User Memory）。每次对话必备。
*   **第 3 层 (前情提要)**：15 个最近对话的轻量摘要（Conversation Summary）。也是持久化的。
*   **第 4 层 (当下)**：当前对话的滑动窗口（Current Session）。
*   *【PM 洞察】*：为什么这么克制？因为作为面向 C 端大众的聊天工具，用户的绝大多数问题并不需要翻找 8 个月前的记录，过度引入深度检索只会拉高 OpenAI 千万级并发下的存储成本和推理延迟。

### 2. 偏向工程的解法：OpenClaw的混合检索 (Hybrid Retrieval)
面对硬核系统（如复杂的量化开发或企业知识库），OpenClaw 采取了更具工程深度的架构：
1.  **流水底层**：`memory/YYYY-MM-DD.md` 追加写日志，一点死角都不漏。
2.  **核心事实舱**：`MEMORY.md` 存放提纯后的核心逻辑规则。
3.  **核心杀手锏 - 混合检索 (Hybrid Search)**：
    *   **70% 的向量搜索 (Vector 语义)** + **30% 的关键词打分 (BM25 字面)**。
*   *【PM 洞察/面试金句】*：
    很多人一上来不管三七二十一就上 Vector DB (向量数据库)。其实对于 Agent 的初期，向量数据库又贵又不好调试。OpenClaw 的这套 **Markdown 结构化文本 + 关键词混合检索** 方案，天生具备三个巨大优势：**可读、可改、可检索**。
    > “在系统起步或记忆条目小于几千条时，直接引入庞大的向量存储是过度设计 (Over-engineering)。基于结构化文本的混合搜索，不仅成本低，而且对于开发者去追查 Agent 的故障非常友好（一看 MD 文件就知道脑浆坏在哪了）。当系统真正起量时，再渐进式升级底层引擎，这才是成熟架构师的做法。”
